## 📋 Descrição

Desafio **"Criação de Repositório com Versionamento"**: desenvolver um repositório no GitHub com projetos acadêmicos e pessoais, aplicando boas práticas de versionamento, colaboração e compartilhamento de código, e integrá-lo ao LinkedIn.

## 🎯 Objetivos

- Planejar as seções e a estrutura de diretórios do repositório.
- Criar uma página web e versioná-la com Git a partir da **versão 1.0**.
- Organizar os projetos em pastas, cada um com seu `README.md`.
- Publicar o site com **GitHub Pages**.
- Tornar o repositório público e integrá-lo ao **LinkedIn**.
- Apresentar o repositório em um vídeo de 5 minutos.

## 🛠️ Tecnologias

- **HTML5** semântico e acessível
- **CSS3** — variáveis, Grid, Flexbox, tema claro/escuro, layout responsivo
- **JavaScript** puro — menu mobile, filtro de projetos, troca de tema, animações
- **Git + GitHub Desktop** — versionamento
- **GitHub Pages** — hospedagem

## ⚙️ Funcionalidades do site

- Layout responsivo (desktop, tablet e celular).
- Tema claro/escuro (segue o sistema e pode ser trocado no botão).
- Filtro de projetos por categoria (acadêmicos / pessoais).
- Links para a documentação de cada parte do repositório.
- Meta tags **Open Graph** para prévia bonita no LinkedIn.

## ▶️ Como executar

```bash
git clone https://github.com/PedroEmilioGea/github-page.git
cd github-page
# abra index.html no navegador
```

### Como foi publicado no GitHub Pages

1. Repositório → **Settings → Pages**.
2. *Source*: **Deploy from a branch** → branch `main`, pasta `/ (root)` → **Save**.
3. A cada `push` na `main`, o site é atualizado automaticamente em alguns minutos.

## 📚 Aprendizados

- Diferença entre **working directory**, **staging area** e **repositório** (local e remoto).
- Uso de **Conventional Commits** e **tags** para marcar versões.
- Organização de um repositório pensando em quem vai lê-lo (recrutadores, professores, colegas).
- Publicação de sites estáticos sem servidor próprio.
